# Jev research protocol v2.1-corrected

Frozen 2026-10-08 before collecting this study. Prompt version: 670894ad859829fc4e80b00f3431a52bf5e06f5e17bfbbc6f1bbf050ca51e016.
Only one prompt version and protocol ID form a study. protocol_id is SHA256 of canonical research_protocol.json, including the SHA256 of this document. Changing either file creates a different study; this implementation rejects unsupported parameter changes. Historical contradictory drafts remain outside the repository.

1. Signals are successful directional decisions BUY/STRONG_BUY (+1), SELL/STRONG_SELL (-1). HOLD/TAKE_PROFIT are logged, not evaluated directionally. The logger stores allowlisted inputs, UTC timestamp and code provenance; dirty code is marked +dirty, unavailable provenance unknown. Different prompt versions are not pooled.
2. H72 is the only primary horizon with a verdict. H24, sides and symbols are descriptive only. For time t and horizon H use 5-minute candle open indices floor(t/300) through floor((t+H)/300)-1. Entry is the close of the first candle whose close is strictly after t; exit is the last close <= t+H. Do not require unused candles before or after this exact set.
3. Barrier diagnostics exclude the entry candle. BUY SL uses low<=SL and TP high>=TP; SELL is the mirror. Same-candle SL/TP resolves to SL. TP2 requires TP1 and must occur before SL. These barriers are diagnostics: ret is hypothetical holding to the horizon, not realized P&L after SL/TP or execution/funding.
4. Signed return = s*(asset_exit/asset_entry-1). Alpha=s*(asset_return-BTC_return). BTC records are excluded from the main alpha test and reported separately using raw signed returns. Benchmark uses XBT/USD with identical timing. BTC/USD is a local alias for XBT/USD.
5. Costs .003 and .005 round-trip are hypothetical scenarios, not verified current fees. Net alpha subtracts each cost. No trading, orders, account keys or funding accounting are performed.
6. H72 requires the exact union of main, minus24h and plus48h windows, for asset and benchmark. Thus full main testing waits for coverage through approximately t+120h. H24-only uses just its own main window. Future candle closes cannot settle even if a cache contains them. Missing/conflicting candles give INCOMPLETE in a separate audit, never an OK ledger row; later complete data may settle. No interpolation or historical pagination.
7. Candle collection is a separate explicit --execute command with default dry-run. Kraken only exposes about720 recent candles (~60h), not recoverable deeper history via since/last. Collect at least every48h (recommended24h). Always drop the last API item and any candle closing after fetch time. last is a cursor, not a clock. The data horizon extends through last signal+120h (H72 plus placebo+48h). Pairs remain eligible for a bounded final catch-up through last signal+180h, including the first collection after +120h; this does not recover older gaps beyond Kraken retention. Older records are reported as past_catchup_records with coverage_status INCOMPLETE; offline settlement determines actual coverage. At least1s between calls,15s timeout,no retries. Conflicting candles are retained as conflicting observations, never overwritten.
8. JSONL is strict: malformed/truncated/nonfinite data blocks the run, rather than selectively skipping it. Identical records/candles/settlements dedup. Conflicting record IDs are excluded; conflicting open_ts makes affected windows incomplete; conflicting OK settlements for the same record/horizon/protocol exclude the result. Hash original record, exact used pair/candle lists and protocol. Evaluation recomputes expected rows from cache before accepting a join. Deterministic OK rows have no run clock; INCOMPLETE goes to a separate audit.
9. Main cohort = non-BTC directional records with a complete H72 battery. t0 is min(ts_utc) across all successful directional records of this prompt, before coverage/BTC exclusions. CR1 blocks=floor((ts-t0)/72h). Greedy per symbol sorted(entry_ts,record_id) selects first and then only entry>=last_selected+72h. Thresholds: main n>=30,elapsed days>=30,non-BTC symbols>=2,main blocks>=10,greedy n>=15,greedy blocks>=10. Before these only SAMPLE_TOO_SMALL with counts; --preview explicitly says PREVIEW — NIE JEST WERDYKTEM.
10. CR1 SE²=g/(g-1)*sum_block(sum_within_block(x-mean))²/n². CI95 uses Student t .975,g-1; CI90 uses .95,g-1. g<2 yields no CI. Zero SE in required main/return/placebo/greedy summaries yields DEGENERATE, not a verdict. MDE≈(t.975+t.80)*SE is an approximation treating SE as known, without exact power claims.
11. EDGE_POSITIVE: lower95% net alpha CI>0 for both costs, and greedy lower95% net CI at .005>0; both placebos have90% CI strictly inside(-.003,.003); fade per record is an exact opposite within1e-9. NO_EDGE:90% alpha CI strictly inside(-.003,.003) on main AND greedy. Otherwise INCONCLUSIVE. MDE is descriptive, not an extra gate. H24/sides/symbols never issue independent verdicts.
12. Exploratory sign permutation:1000 draws,seed20261008,one shared sign per entire72h block; two-sided p=(1+number_abs_permuted>=abs_observed)/1001. This does not affect verdicts. Dependence between symbols and adjacent blocks remains unmodeled; greedy removes overlapping horizons per symbol only. The cohort is selected by user-triggered analyses, not all possible market signals. No result guarantees investment profitability.

## Commands (repository root)

```
../jev-test-env/bin/python scripts/collect_candles.py --log app/data/decisions.jsonl --candles app/data/candles
# Collection network is only authorized separately: same command with --execute.
../jev-test-env/bin/python scripts/settle_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --output app/data/decisions.settled.jsonl --audit app/data/settle_incomplete.jsonl --horizon H24
../jev-test-env/bin/python scripts/settle_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --output app/data/decisions.settled.jsonl --audit app/data/settle_incomplete.jsonl --horizon H72
../jev-test-env/bin/python scripts/evaluate_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --settlements app/data/decisions.settled.jsonl
```

Settlement/evaluation are offline and do not import app settings or .env. Optional --now is a reproducibility clock and never authorizes future candles. Default decisions path can be overridden by JEV_DECISION_LOG; no scripts modify the original journal. Normal analyses log success/degraded/unavailable; write failures expose only a closed category. State/questions AST defines prompt_version without changing model semantics.

Operational integrity: prompt/code provenance is captured at module initialization; journal writes run off the asyncio event loop. Failed writes expose a neutral correlation ID and a persistent UI warning until a confirmed write. No automatic tail truncation occurs. The offline repair_decision_log.py command defaults to dry-run; --apply only repairs recognizable truncated tails after validating the complete prefix and durably quarantining the tail under an exclusive lock. Earlier corruption is not repaired. Quarantine and journal require private0600 regular files, without following journal symlinks.

Collection attempts benchmark XBT/USD first, isolates each pair failure, continues other pairs and reports PARTIAL/BLOCKED with nonzero exit for any failure. Cache corruption blocks that pair without replacement. Settlement deduplicates identical INCOMPLETE observations while preserving changes in coverage and later OK results.
