# Jev research protocol v2.2

Version 2.2 frozen 2026-10-10; legacy v2.1 remains a separate protocol. Prompt version: 670894ad859829fc4e80b00f3431a52bf5e06f5e17bfbbc6f1bbf050ca51e016.
Only one (prompt_version, inputs_version, protocol_id) triple forms a study. protocol_id is SHA256 of canonical research_protocol.json, including the SHA256 of this document. Changing either file creates a different study; this implementation rejects unsupported parameter changes. Historical contradictory drafts remain outside the repository.

1. Signals are successful directional decisions BUY/STRONG_BUY (+1), SELL/STRONG_SELL (-1). HOLD/TAKE_PROFIT are logged, not evaluated directionally. The logger stores allowlisted inputs, UTC timestamp and code provenance; dirty code is marked +dirty, unavailable provenance unknown. Different prompt versions are not pooled.
2. H72 is the only primary horizon with a verdict. H24, sides and symbols are descriptive only. For time t and horizon H use 5-minute candle open indices floor(t/300) through floor((t+H)/300)-1. Entry is the close of the first candle whose close is strictly after t; exit is the last close <= t+H. Do not require unused candles before or after this exact set.
3. Barrier diagnostics exclude the entry candle. BUY SL uses low<=SL and TP high>=TP; SELL is the mirror. Same-candle SL/TP resolves to SL. TP2 requires TP1 and must occur before SL. These barriers are diagnostics: ret is hypothetical holding to the horizon, not realized P&L after SL/TP or execution/funding.
4. Signed return = s*(asset_exit/asset_entry-1). Alpha=s*(asset_return-BTC_return). BTC records are excluded from the main alpha test and reported separately using raw signed returns. Benchmark uses XBT/USD with identical timing. BTC/USD is a local alias for XBT/USD.
5. Costs .003 and .005 round-trip are hypothetical scenarios, not verified current fees. Net alpha subtracts each cost. No trading, orders, account keys or funding accounting are performed.
6. H72 requires the exact union of pre72, main and post72 windows, for asset and benchmark. Nominal windows are [t-72h,t], [t,t+72h], [t+72h,t+144h], with offsets [-72,72] committed in protocol parameters. Their candle open-index sets are pairwise disjoint. Each set contains 864 candles but entry at its first close means 863 close-to-close return intervals (71h55m); the boundary interval between adjacent sets is omitted, not counted twice. These are nominal H72 windows, not exactly 72 hours held. Full testing waits through approximately t+144h; missing pre72 remains INCOMPLETE. The first 72 hours of tracking a new symbol do not supply an eligible pre72 history. Shared boundary prices in alternative representations would not themselves imply overlapping return intervals. H24-only uses just its own main window. Future candle closes cannot settle even if a cache contains them. Missing/conflicting candles give INCOMPLETE in a separate audit, never an OK ledger row; later complete data may settle. No interpolation or historical pagination.
7. Candle collection is a separate explicit --execute command with default dry-run. Kraken only exposes about720 recent candles (~60h), not recoverable deeper history via since/last. Collect at least every48h (recommended24h). Always drop the last API item and any candle closing after fetch time. last is a cursor, not a clock. The data horizon extends through last signal+144h (H72 plus post72). --track ETH,SOL,XRP keeps those pairs and XBT/USD collecting even without decisions; symbols must match [A-Z0-9]{1,15}, benchmark first, default dry-run reports requests:0. Pairs remain eligible for a bounded final catch-up through last signal+180h, including the first collection after +144h; this does not recover older gaps beyond Kraken retention. Older records are reported as past_catchup_records with coverage_status INCOMPLETE; offline settlement determines actual coverage. At least1s between calls,15s timeout,no retries. Conflicting candles are retained as conflicting observations, never overwritten.
8. JSONL is strict: malformed/truncated/nonfinite data blocks the run, rather than selectively skipping it. Identical records/candles/settlements dedup. Conflicting record IDs are excluded; conflicting open_ts makes affected windows incomplete; conflicting OK settlements for the same record/horizon/protocol exclude the result. Hash original record, exact used pair/candle lists and protocol. Evaluation recomputes expected rows from cache before accepting a join. Deterministic OK rows have no run clock; INCOMPLETE goes to a separate audit.
9. Main cohort = non-BTC directional records with a complete H72 battery. t0 is min(ts_utc) across all successful directional records of this prompt and inputs version, before coverage/BTC exclusions. CR1 blocks=floor((ts-t0)/72h). Greedy per symbol sorted(entry_ts,record_id) selects first and then only entry>=last_selected+72h. Thresholds: main n>=30,elapsed days>=30,non-BTC symbols>=2,main blocks>=10,greedy n>=15,greedy blocks>=10. Before these only SAMPLE_TOO_SMALL with counts and descriptive n_needed estimates (no other outcome statistics); --preview explicitly says PREVIEW — NIE JEST WERDYKTEM.
10. CR1 SE²=g/(g-1)*sum_block(sum_within_block(x-mean))²/n². CI95 uses Student t .975,g-1; CI90 uses .95,g-1. g<2 yields no CI. Zero SE in required main/return/placebo/greedy summaries yields DEGENERATE, not a verdict. MDE≈(t.975+t.80)*SE is an approximation treating SE as known, without exact power claims.
11. EDGE_POSITIVE: lower95% net alpha CI>0 for both costs, and greedy lower95% net CI at .005>0; both pre72 and post72 placebos have90% CI strictly inside(-.003,.003); fade per record is an exact opposite within1e-9. NO_EDGE:90% alpha CI strictly inside(-.003,.003) on main AND greedy. Otherwise INCONCLUSIVE. MDE is descriptive, not an extra gate. H24/sides/symbols never issue independent verdicts.
12. Descriptive beta: intercept OLS of asset simple close-to-close 5-minute returns on XBT from pre72, minimum 100 paired observations. Zero benchmark variance, missing observations or nonfinite estimation gives beta=null with a closed reason. alpha_beta_adj=s*(asset_return-beta*BTC_return), summarized with the same CR1 blocks on available records only, is descriptive and never enters any verdict. H24 does not require pre72 and reports beta unavailable. Descriptive n_needed_no_edge is the minimum integer n_new>=n with t(.95,g_new-1)*SE*sqrt(n/n_new)<delta; g_new=max(2,floor(g*n_new/n)). n_needed_edge_positive uses t(.975) and width mean-max(costs); mean<=cost gives null/reason. g<2 or zero SE gives null/reason. Search is bounded at 10,000,000 records (larger observed n is search_limit). These fixed-SE/fixed-mean scaling approximations are CI precision estimates, not power or promised verdicts. Narrowing CI alone cannot guarantee NO_EDGE when the mean is displaced from zero. Estimates do not change gates, thresholds or costs.

Exploratory sign permutation:1000 draws,seed20261008,one shared sign per entire72h block; two-sided p=(1+number_abs_permuted>=abs_observed)/1001. This does not affect verdicts. Dependence between symbols and adjacent blocks remains unmodeled; greedy removes overlapping horizons per symbol only. The cohort is selected by user-triggered analyses, not all possible market signals. No result guarantees investment profitability.

13. Input-version policy: inputs_version hashes canonical AST for the whole StatsService.process_tweets method, FEAR_KEYWORDS, GREED_KEYWORDS, TwitterService._build_query including its symbol-name dictionary, and the default SOCIAL_WINDOW_HOURS. It excludes comments, formatting and unrelated imports. Startup captures this fingerprint once; each journal record carries it. Missing/different versions are excluded by settle/evaluate with excluded_inputs_version counts over unique nonconflicting records, including nondirectional records. Prompt definitions remain unchanged. Malformed present version types/hashes block; historical absence is excluded, not relabeled. Settlements join by record/candle/protocol hashes and input version; never reuse old rows lacking the new contract. Runtime window overrides remain a known limitation of a default-definition fingerprint. The external CC read-only report stated v2.1 had zero settlements at handoff; this offline implementation did not inspect real data or establish that current fact. Regardless, protocol versions are never pooled.
14. Known prompt-v1 limitations retained: question 3 refers to support levels absent from state; rationale is generated by rules, not a model explanation; selected posts carry high_engagement/latest_breaking type flags; trade levels use fixed percentages rather than volatility. None is corrected by v2.2 and no prompt/threshold change is implied.

## Commands (repository root)

```
../jev-test-env/bin/python scripts/collect_candles.py --track ETH,SOL,XRP --log app/data/decisions.jsonl --candles app/data/candles
# Collection network is only authorized separately: same command with --execute.
../jev-test-env/bin/python scripts/settle_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --output app/data/decisions.settled.jsonl --audit app/data/settle_incomplete.jsonl --horizon H24
../jev-test-env/bin/python scripts/settle_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --output app/data/decisions.settled.jsonl --audit app/data/settle_incomplete.jsonl --horizon H72
../jev-test-env/bin/python scripts/evaluate_decisions.py --log app/data/decisions.jsonl --candles app/data/candles --settlements app/data/decisions.settled.jsonl
```

Settlement/evaluation are offline and do not import app settings or .env. Optional --now is a reproducibility clock and never authorizes future candles. Default decisions path can be overridden by JEV_DECISION_LOG; no scripts modify the original journal. Normal analyses log success/degraded/unavailable; write failures expose only a closed category. State/questions AST defines prompt_version without changing model semantics.

Operational integrity: prompt/code provenance is captured at module initialization; journal writes run off the asyncio event loop. Failed writes expose a neutral correlation ID and a persistent UI warning until a confirmed write. No automatic tail truncation occurs. The offline repair_decision_log.py command defaults to dry-run; --apply only repairs recognizable truncated tails after validating the complete prefix and durably quarantining the tail under an exclusive lock. Earlier corruption is not repaired. Quarantine and journal require private0600 regular files, without following journal symlinks.

Collection attempts benchmark XBT/USD first, isolates each pair failure, continues other pairs and reports PARTIAL/BLOCKED with nonzero exit for any failure. Cache corruption blocks that pair without replacement. Settlement deduplicates identical INCOMPLETE observations while preserving changes in coverage and later OK results.
